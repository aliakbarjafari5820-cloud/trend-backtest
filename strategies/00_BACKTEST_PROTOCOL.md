# دستورالعمل بک‌تست — مقایسهٔ علمی سه استراتژی

> این فایل برای هر سه استراتژی مشترکه. فایل‌های 01، 02 و 03 فقط «قوانین ورود» رو تعریف می‌کنن؛ بقیهٔ چیزها اینجاست.
> پیاده‌سازی مرجع: `smc/engine.py` (موتور)، `smc/run_shard.py` (داده)، `smc/aggregate.py` (گزارش)، `smc/test_engine.py` (تست واحد).

## ۱. هدف
مقایسهٔ منصفانهٔ Classic Price Action، Smart Money Concepts و Hybrid با **یک دیتاست، یک موتور، کارمزد، اسلیپیج و سرمایهٔ یکسان**.
برنده فقط با بیشترین سود انتخاب نمی‌شه؛ پایداری سود، افت سرمایه، تعداد معاملات و عملکرد خارج از نمونه مهم‌ترن.

## ۲. داده
| مورد | مقدار |
|---|---|
| بازار | همهٔ قراردادهای Binance USDT-M Perpetual، **شامل نمادهای حذف‌شده** (جلوگیری از سوگیری بقا) |
| منبع | `data.binance.vision` — کندل‌های ماهانهٔ ۵ دقیقه‌ای + نرخ فاندینگ ماهانه |
| بازه | ۲۴ ماه کامل آخر |
| تایم‌فریم‌ها | 5m (داده خام)، 15m و 1h (از روی همان 5m ساخته می‌شن تا داده یکسان باشه) |
| حداقل تاریخچه | کمتر از ۸٬۶۴۰ کندل ۵ دقیقه‌ای (۳۰ روز) → «insufficient_history»، بررسی نمی‌شه |
| کیفیت داده | برای هر نماد ثبت می‌شه: ماه‌های موجود، کندل‌های گم‌شده، گپ‌های بالای ۱ ساعت، وجود فاندینگ، وضعیت (ok / partial / insufficient_history / no_data_in_period) |

## ۳. تعریف‌های مشترک (عددی و ثابت برای همهٔ ارزها و تایم‌ها)
| مفهوم | مقدار |
|---|---|
| سوئینگ | High اکیداً بالاتر از ۲ کندل چپ و ≥ ۲ کندل راست (کف برعکس). فقط بعد از بسته شدن کندل دومِ راست معتبره. |
| ATR | دورهٔ ۱۴ (میانگین سادهٔ True Range) |
| حداقل قدرت شکست | کلوز حداقل **۰.۵ ATR** اون‌ور سطح. فقط اولین کلوزی که از این آستانه رد بشه شکست حساب می‌شه؛ هر سطح یک بار. |
| تلورانس پولبک | قیمت تا فاصلهٔ **۰.۲۵ ATR** از سطح شکسته‌شده برگرده |
| ابطال شکست | کلوز ۰.۵ ATR اون‌ور سطح در جهت مخالف |
| کندل تأیید | خرید: کلوز > اپن و کلوز بالای سطح (یا لبهٔ پایین ناحیه). فروش برعکس. |
| ورود | اپن کندل **بعد** از کندل تأیید (هیچ تصمیمی با کندلِ هنوز بسته‌نشده گرفته نمی‌شه) |
| فاصلهٔ محافظتی حد ضرر | ۰.۱ ATR |
| محدودهٔ مجاز حد ضرر | بین **۰.۱ تا ۳ ATR** از قیمت ورود؛ بیرون از این محدوده → معامله انجام نمی‌شه |
| حد سود | **۲R خالص**: فاصلهٔ حد سود = ۲ × ریسک + هزینهٔ کارمزد و اسلیپیج ورود و خروج |

## ۴. اجرای معامله و هزینه‌ها
| مورد | مقدار |
|---|---|
| سرمایهٔ اولیه | ۱۰٬۰۰۰ USDT |
| ریسک هر معامله | حداکثر ۱٪ اکوئیتی لحظهٔ ورود |
| کارمزد | Taker ۰.۰۵٪ هر طرف |
| اسلیپیج | ۰.۰۲٪ هر طرف |
| فاندینگ | نرخ واقعی هر ۸ ساعت بین ورود و خروج (لانگ نرخ مثبت رو می‌پردازه، شورت دریافت می‌کنه). بدون داده → ۰.۰۱٪ هر ۸ ساعت به ضرر معامله |
| اهرم | حداکثر ۲۰x؛ اگه ۱٪ ریسک اهرم بیشتری بخواد، حجم (و ریسک واقعی) کم می‌شه |
| لیکویید | مارجین ایزوله، مارجین نگهداری ۰.۵٪. اگه ضرر واقعی (مثلاً با گپ) از فاصلهٔ لیکویید بیشتر بشه، معامله لیکویید ثبت می‌شه |
| SL و TP در یک کندل | ضرر حساب می‌شه (محافظه‌کارانه) |
| گپ از حد ضرر | خروج روی اپن کندل |
| تداخل سیگنال | هر ارز/استراتژی/تایم فقط یک معاملهٔ باز. در کل سبد حداکثر **۳ معاملهٔ همزمان**؛ سیگنال‌های هم‌زمان با ترتیب تصادفی ثابت (seed=42) |

## ۵. جلوگیری از Lookahead و Data Leakage
- سوئینگ فقط بعد از تأیید (۲ کندل بعد) استفاده می‌شه.
- ATR، روند و همهٔ شرط‌ها فقط با کندل‌های بسته‌شده تا لحظهٔ تصمیم.
- ورود روی اپن کندل بعدی.
- پارامترها قبل از دیدن نتایج ثابت شدن و برای هیچ ارز یا تایمی جدا تنظیم نمی‌شن.
- تست واحد: روی قیمت تصادفی (random walk) میانگین R قبل از هزینه نباید معنادار مثبت باشه.

## ۶. ارزیابی
- **تقسیم زمانی:** ۶۰٪ اول توسعه، ۲۰٪ بعد اعتبارسنجی، ۲۰٪ آخر تست نهایی خارج از نمونه (هر بخش جدا با ۱۰٬۰۰۰ USDT).
- **Walk-Forward:** پنجرهٔ ۶ ماه آموزش → انتخاب بهترین ترکیب (استراتژی × تایم) با Calmar → اجرا روی ۳ ماه بعد؛ هر ۳ ماه جلو.
- **رژیم بازار:** روزانهٔ بیت‌کوین؛ صعودی = کلوز و SMA50 بالای SMA200، نزولی = هر دو زیر SMA200، بقیه خنثی.
- **معیارها:** Net Profit، Profit Factor، Win Rate، Maximum Drawdown، Expectancy (R)، Total Trades، Average Win/Loss، Sharpe، Sortino، Calmar (روزانه، سالانه‌شده با √365)، عملکرد لانگ/شورت، تعداد لیکوییدها، درصد ارزهای سودده.
- **خروجی‌ها:** `results/summary.csv`، `results/by_tf/`، `results/by_coin.csv`، `results/split_60_20_20.csv`، `results/walk_forward.csv`، `results/by_regime.csv`، `results/by_setup.csv`، `results/data_quality.csv`، `results/answers.json`، `results/report.txt`
